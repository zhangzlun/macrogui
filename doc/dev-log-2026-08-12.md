## 1. 專案建置與環境問題

- 以 uv 建立專案（`uv init --bare`），期間升級 uv 0.5.11 → 0.12.3（舊版不支援 `--bare`）
- 依賴宣告：`pynput`＋平台限定 `pyobjc-framework-quartz`（macOS）、`pydirectinput`（Windows）
- **關鍵環境修正**：uv 預設的 python-build-standalone 3.12.8 綁 Tcl/Tk 8.6.12，在新版 macOS 有嚴重的 aqua 事件 bug（下拉選單點不到）。改釘 python.org 3.14 framework build（Tk 8.6.17），`.python-version` 指到絕對路徑

## 3. 執行模型演進

三次迭代收斂到最終架構：

1. **巨集有模式屬性**（冷卻/循序/組合）→ 發現模式切換清空清單且資料被 auto-commit 蓋掉 → 改為各模式清單獨立保存
2. **常駐輪替＋熱鍵插播**：冷卻/循序＝F8 啟動後常駐；組合＝熱鍵插播（輪替暫停、打完自動恢復、再按取消）。但「模式停錯位置就說沒資料」的死角仍在
3. **最終架構（存檔 v3）**：徹底移除模式概念——每個角色＝一份「技能輪替」（主畫面直接編輯）＋任意數量「組合」（列表全列、彈窗編輯、各綁熱鍵）。舊格式自動升級（循序轉為無限輪＋固定間隔的組合，行為等價）

插播語意：組合執行期間輪替暫停（避免按鍵互相插隊），N 輪打完經 msg_q 由主執行緒自動恢復；切換輪替對象時舊現場保留為後路，新輪替啟動成功才丟棄。

## 4. 功能增補

- **控制熱鍵可自訂**：輪替開關（預設 F8）與結束程式（預設 F9）皆可改綁，支援組合鍵，衝突保護拒絕已占用的鍵；按鈕/狀態列/卡片提示文字動態顯示
- **視窗標題下拉選單**：「只在視窗標題含」改為列出目前開啟視窗的可輸入下拉選單（macOS System Events / Windows EnumWindows），附重新整理
- **滑鼠點擊步驟**：組合步驟支援按鍵與點擊混排；點擊＝目標視窗＋相對座標（視窗移動也點得準）＋左/右/中鍵；F10 抓取模式自動換算座標；三平台視窗定位（Win32 GetWindowRect、macOS Quartz CGWindowList、Linux wmctrl）
- **系統通知**：輪替開始/停止、組合單獨執行完成、錯誤、程式結束時發 macOS 通知中心橫幅（osascript，零依賴）；插播刻意靜默；全域設定可關閉
- **技能監看**：框選畫面上的技能圖示區域（F10×2）、技能存在時拍基準圖（3 秒倒數），mss 擷取＋24×24 取樣指紋比對（對 Retina 縮放不敏感）；相似度低於門檻→最上層紅色警報視窗（已消失秒數即時更新）＋每 2 秒警示音；恢復自動解除、「知道了」恢復前靜音。macOS 需授權螢幕錄製

## 5. 工程慣例

- 每項功能皆以假後端（記錄按鍵/點擊而不真發）的自動化場景測試驗證，UI 以截圖驗收
- 主執行緒與 worker/擷取執行緒之間一律走 msg_q，不跨執行緒碰 Tk
- 個人設定 `profiles.json` 不進版控
